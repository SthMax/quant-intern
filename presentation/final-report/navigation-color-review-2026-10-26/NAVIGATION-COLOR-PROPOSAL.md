# 导航层级与主线配色方案

本文件是方案说明。导航、颜色和相关页面尚未修改。本轮成品只修正第11页询价记录的提供者及LLM职责。

## 判断

目前有两个组织层次：整篇按前台、中台、后台展开；每个业务主题按工作任务、同行做法、公司方案展开。左侧地图已经能够回答“在哪个部门、讨论哪个主题”，副标题却只是把当前阶段写出来，没有让观众看到这个主题已经讲到哪里、后面还剩什么。

两条贯穿对象也缺少稳定标记。第3和30页用青绿色表示甲公司、紫色表示客户沟通稿，但正文的计算工具、查询系统、文件工具也用了青绿色。客户沟通稿本身的标题、边框和文字标签仍以蓝色为主。观众很难从同一颜色持续认出同一个对象。

推荐保留现有白蓝版式，分别用固定位置的进度、主线颜色与明确角色文字承担不同信息。

## 推荐导航：左栏定位主题，副标题行显示三步，页脚补充页次

### 1. 左侧公司地图继续承担章节和主题定位

- 保留前台、中台、后台与七个任务名称。
- 当前部门的栏头使用深蓝，当前任务用浅蓝底和粗体，其余保持浅灰。
- 左栏只表示正在讨论的业务主题，不表示工作任务、同行做法或公司方案，也不使用青绿、紫色。
- 在第29、30等跨部门汇总页，不把某一个任务标成当前任务。第3、29页总图直接显示全篇视图。

### 2. 复用标题下现有一行，增加三个明确的阶段

以当前1600×900画布为基准，标题区、正文起点和底部按钮均保留。调整现有副标题行即可，不再往正文上方增加一排内容。

| 位置 | 显示内容 | 建议范围 |
|---|---|---|
| 副标题行左端 | `前台 / 研究分析`等短定位 | x=68–378，y约125，字号24px |
| 副标题行中部 | `1 工作任务　2 同行做法　3 公司方案` | x=426–1150，三段各约230px，字号24px |
| 副标题行右端 | 青绿`甲公司`或紫色`客户沟通稿`，必要时附灰色版本/用途 | x=1204–1460，字号22–24px |

最右端现有“示例”标识继续放在x=1472–1532，主线标签与它留出间距。

当前阶段用深蓝粗体，并在该段文字下方加一条短蓝线。其他两段用灰色，不用绿色表示完成，也不把三个阶段各分配一种颜色。观众由选中的文字就能知道正在讲哪一步。

案例占多页时，“2 同行做法”持续选中，页脚的本题页次继续递增。例如研究主题第5、6、7页均选中“2 同行做法”，页脚分别显示“本题第2/5页”“本题第3/5页”“本题第4/5页”，页面标题已经指出天弘、富国和中欧。第10页同页有两家公司，仍按一张幻灯片计数。

不再另加“案例1/3”计数，也不把阶段写成“2/3”。三步只用固定的1、2、3标识顺序，页脚只保留本题页次和全稿页码，两者都明确写出名称。

如果以后实施此方案，三个阶段名可直接跳到当前主题的相应起始页。现有“下一步”仍按全稿顺序前进，不改变线性讲述。

### 3. 页脚同时给本题页次和全稿页码

沿用上一页、下一页按钮前的空白区域，建议用约285px宽的灰色文字显示`本题第2/3页　全稿10/33`。这里“本题”统计该业务主题包含的实际幻灯片，不把多页案例误算为多个工作阶段。

七个主题的范围：研究4–8页，共5页；交易9–11页，共3页；客户材料12–15页，共4页；审核16–18页、风险19–21页、文件22–24页、开发25–27页各3页。

封面、研究范围、公司总图、后台其他应用及最后汇总页不显示三步进度，也不显示“本题”页次。第29–33页使用“建议汇总”“资料协作”“共用条件”“实施顺序”“效果评价”等现有内容定位，并保留全稿页码，避免硬套一个不存在的业务主题。

## 完整颜色语义

| 用途 | 色值 | 出现载体与用量 |
|---|---|---|
| 品牌及导航强调 | 深蓝`#005A9C`，浅蓝`#D9EAF7` | 部门栏头、当前任务、阶段短下划线、主要标题。蓝色不再专指LLM这一种角色。 |
| 甲公司主线 | 青绿`#317F7B`，极浅底`#EFF6F4` | 固定`甲公司`小标签，相关财报、持仓、报价、分析文档的细色条或标题标记。每页通常一个主线标签，加少量对象标记。 |
| 客户沟通稿主线 | 紫色`#7363A6`，极浅底`#F3F0F8` | 固定`客户沟通稿`小标签，同一稿件V1、V2、审核引用和变更说明的文档标题线/侧边细条。版本仍用文字标识。 |
| 人、LLM、工具 | 白色`#FFFFFF`、浅灰`#F3F7FA`，正文`#20262C`，边线`#BCC6CF` | 角色块统一使用中性底色，以“研究员提出问题”“LLM比较观点”“计算工具返回”等完整短语说明分工。角色差异靠文字和图中的关系，不再分配青绿、紫色。 |
| 被讨论的文字差异 | 淡黄`#FFF0BE` | 只标出需要查看的变化位置。原文、修订后、待修改、已更新都用文字说明，黄色不表示通过或失败。 |
| 次要说明与未选中项 | 灰色`#707C88` | 来源、非当前阶段、本题页次、版本补充文字。 |

青绿和紫色是“哪个对象正在被处理”的标识，不表示前台/中台/后台、不表示工作任务/同行/方案，也不表示计算工具、完成状态或审核通过。换部门或换阶段时，主线颜色保持不变。

正文仍以白底、黑字、蓝色导航为主。主线色优先用于6px左右的文档侧条、细标题线和短名字，通常不超过正文面积的10%。只有第3、30页同时比较两条主线时，才可以使用较大的极浅绿/极浅紫区域，正文文字仍保持黑色。

## 主线怎样持续出现

- 第4–8页：`甲公司`标记跟随财报、纪要、观点比较和公司分析。同行方法页可在标签旁加灰色“方法参考”，不改变案例公司的名称。
- 第9–11页：同一青绿标记跟随甲公司债券、询价条件、候选券和报价资料。查询系统本身使用中性底色。
- 第19–21页：青绿标记跟随甲公司事件、相关持仓和影响说明，模型与查询工具保持中性角色块。
- 第12、13、15–18页：紫色标记跟随季度沟通稿的准备、V1、原文对照和V2。第14页是独立的机构标书案例，不把它标成同一份客户沟通稿，使用中性的“机构标书案例”说明。
- 第22、23页：紫色只落在涉及客户稿版本的内容上，传真识别等通用材料保持中性。同页出现甲公司资料时，给该对象单独的青绿标签，不给整页选择一种主线色。第24页的输入V1/V2和输出变更说明均以紫色说明所属稿件，但明确写出各自名称。
- 第25–27页：用客户沟通稿作为报告比对开发样例时，紫色只标记两版输入文件，旁边写“开发样例”。开发人员、代码和测试工具不整块染紫。
- 第28页其他应用和第31页共用服务保持中性。第29、30页可并列放两个固定名字，收束两条主线，不把所有内容归到某一种主线色。

## 当前冲突与将来的对应处理

| 当前用法 | 主要位置 | 推荐处理 |
|---|---|---|
| 工具、业务系统使用青绿底和青绿字 | 8、9、10、11、18、20、21、23、24、27、31等 | 改为白/灰角色块，名称明确写“工具”“系统”及动作。相关甲公司数据另用小青绿对象标记。 |
| 客户沟通稿V2的修订文字用浅绿色 | 18页 | 改为淡黄差异定位，写“修订后”。稿件归属用紫色标题线和`客户沟通稿 V2`表示。 |
| 开发支持的总结条也使用青绿色 | 26页 | 改为浅灰或白底，青绿色只给甲公司资料。 |
| 紫色主要出现在全景与收束 | 3、30页 | 保留其主线含义，并将同样的名字与紫色文档标记延续到客户稿相关正文页。 |
| LLM专用浅蓝、当前导航也用蓝 | 多数方案页及全部导航 | 蓝色收回为统一品牌/导航强调。角色依靠清楚名称与中性框，不要求观众记一套角色颜色。 |
| 同一主题只有当前阶段文字，没有进度 | 4–27页 | 在现有副标题行显示三步并选中当前一步，多页案例保持同一阶段选中，本题页次继续递增。 |

这是一套单一推荐方案，不需要额外选择不同配色体系。确认方向后，可按上述规则更新导航和颜色，本轮尚未实施。

## 第11页本轮实际修正

将“LLM读取对手聊天”改为“LLM解析询价记录”，正文明确记录由交易员提供、内容来自收到的卖方报价；LLM提取券名、净价和面额，归并查询结果与报价，交易员核对出处和时间。讲者备注同步说明交易员询价并提供消息/记录。

第9页已经清楚标出交易员向交易对手询价、对手返回报价，没有同类的主动读取表述。本轮保留第9页原样。
