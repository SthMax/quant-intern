# 本地LLM做实际任务：证据、候选与PoC取舍

研究日期：2026-09-09。目标来自用户澄清及[mentor确认计划](../../PROJECT_PLAN.md)：在实习机构/COD环境评估本地部署LLM的可行性，并在本地GPU上完成一个金融NLP任务及延迟测试。本文是研究与选题依据，尚未安装模型、运行推理/回测或完成PoC。

核心判断：**把“本地LLM能做什么、做得是否正确、消耗多少资源”作为主线。** 基金案例提供业务与部署证据，公开论文/代码提供可复用的实现与评价细节；两者分别归因。传统计算器、数据库和回测器可以作为工具，但LLM须实际承担理解、生成、规划或语义推理职责。

## 1. 目前更值得落到本地的三个任务

| 优先级与任务 | LLM做什么 | 本地系统怎样组织 | 第一阶段可检验结果 |
|---|---|---|---|
| **首选：因子描述→代码→校验** | 理解自然语言因子定义、时间窗口和约束，生成Python实现；可在受控次数内读错误反馈修改 | 本地LLM→代码提取/静态检查→隔离执行器→固定行情样本与参考实现→评价记录 | 可执行率、时间因果一致性、数值/边界正确率、修复轮数；同时测生成延迟、token、显存。先验证实现能力，再扩展到新因子搜索 |
| **备选：研报/公告多文档问答** | 根据检索到的证据回答、对比、归纳，并给出处 | 本地LLM＋本地Embedding＋文档/向量库；固定资料截止日，返回原文片段及文档ID | 答案事实正确率、引用支持率、缺证拒答、多文档冲突处理、延迟与内存；与不检索的同一模型比较 |
| **扩展：文本→事件/情绪信号** | 依照任务描述提取主体、事件、方向、时间和证据，支持多个语义任务 | 本地LLM输出结构化记录→schema/实体/时点校验→确定性的因子聚合与研究工具 | 先评字段准确率、遗漏/幻觉、稳定性及成本，再检验相对量价基线的样本外增量；不能把语言解释直接当作alpha |

本地化的对象应包括主LLM、必要的Embedding及任务数据处理。API/gRPC只是调用方式，API地址在本地也可以实现本地推理；反之，客户端在本机而模型仍调用云端，不满足主LLM本地运行的PoC要求。公开数据可以预先下载固化，外部实时数据依赖需单列。模型下载、预处理、建索引、LLM推理和工具执行各自记录，不混算耗时。

## 3. 可复用的本地实现与评价材料

### AlphaQT-Bench：最贴近量化部门的任务评价

[ACL 2026论文](https://aclanthology.org/2026.findings-acl.138/)已保存[16页原PDF](../reference/local-llm/alphaqt-bench/source.pdf)。作者为中国移动九天研究院及高校，属于外部方法参考。

论文第16页Figure 7给出完整系统Prompt：输入为日频DataFrame，字段为`day_open/day_high/day_low/day_close/day_volume`；返回与原时间轴对齐的Series，并要求处理缺失、遵守时间因果和指定代码格式。第5–6页将评价拆成执行成功、时间因果、功能正确、结构合规四层。

最有价值的检查是**动态截断**：同一段历史在完整时间序列中算出的t日输出，应与仅提供t日以前数据时一致。它能发现一类未来信息使用问题，但有限样本通过不是形式化安全证明。论文对数值正确性允许相关性/误差阈值，我们若测单位敏感或阈值策略，应补严格数值与边界检查；“禁循环”属于该基准的任务约束，不是全部量化系统的通用规则。

重要边界：论文第12页说明模型经OpenRouter调用，**不是本地部署实验**；第14页的毫秒耗时测的是生成程序执行，不是LLM推理。不能把表格直接用于我们的GPU延迟/TCO。已定位完整Prompt和协议，本轮未找到完整公开基准代码/Golden Code包；因此借鉴协议并自建明确标注的小测试集，不能声称已经复制原基准成绩。

### AlphaFin：已核对到真实本地RAG推理路径

[论文](https://aclanthology.org/2024.lrec-main.69/)与[固定版本代码](https://github.com/AlphaFin-proj/AlphaFin/tree/068d93eade3957f09279f88c7e47321207ad509)提供ChatGLM2-6B、StockGPT LoRA、BGE与FAISS组成的金融问答流程。开发单位为华南理工与阿里，不能计为基金公司案例。

已逐项核对：`scripts/stage2_financial_qa.sh`传本地模型路径；`src/stage2_financial_qa/webui/run.py`在CPU运行Embedding，在`cuda:0`加载LLM＋LoRA；从本地索引检索，构造中文“基于参考内容回答”Prompt，再调用`model.chat`。界面默认Top-K=5，返回回答和检索文本。这个链路明确由本地LLM做语义回答，并非只有一个外部API客户端。

原项目给有论文、源码、[adapter](https://huggingface.co/AlphaFin/StockGPT-Stage2)、[数据集](https://huggingface.co/datasets/AlphaFin/AlphaFin-dataset-v1)与结果/局限，材料要素丰富。尚未实测，也有具体移植问题：

- ChatGLM2是历史基座，`model.chat`接口与其他模型不同，换模型需适配；不得把旧代码可读等同最新版依赖下直接可运行。
- 已读处理函数只区分“仅检索”和其余生成模式，界面上的单知识/整合知识模式没有独立实现；不能照UI文案声称两种策略都已验证。
- 自动补当前日期会影响复现实验，测试应固定资料与提问截止日；还需在输出中保留原文ID/页段与引用验证。
- 原数据集预览含一般新闻，不能整库当作金融高质量语料；本轮未下载全数据或预建pickle/FAISS文件。模型、adapter和数据许可需分别核对。
- 论文第7页使用A800 80GB进行训练，不等于本地推理最低需要80GB，也不证明某个较小GPU一定能承载目标上下文。

这里可借用的是本地金融问答架构与实现，不采纳论文的收益数字为我们可实现的投资效果。

### FinGPT：金融文本任务的本地基线材料

[官方仓库](https://github.com/AI4Finance-Foundation/FinGPT/tree/781a7c020da977092f2f2c4916024a412c5e3801)与[指令微调论文](https://arxiv.org/abs/2310.04793)提供本地金融情绪、关系抽取、实体识别等任务示例。已存README、SETUP、许可、基准notebook及依赖工具代码，未执行notebook。

代码确实通过Transformers/PEFT加载生成式LLM和LoRA，不是FinBERT分类器。不过这些任务在本项目中应服务于文本信号处理或作为金融NLP基线，不能仅凭三分类准确率就认定有alpha。

发现官方`SETUP.md`的一个示例将Llama-2 **7B**基座与**13B**情绪adapter组合，不能原样采用；实际`benchmarks_llama2_13b.ipynb`使用13B基座与13B adapter、8bit和CUDA。任务notebook另有匹配的7B/6B多任务模型组合。后续必须按具体组合核对，不能照通用硬件推荐推断显存需求。README中的旧训练费用也不作我们的当前TCO。

### RD-Agent：后续自动研发扩展

原有[RD-Agent审查](../reference/quant-methods/README.md)仍适用。其模型后端可配置模型名和API base，**架构上可尝试接本地兼容服务**，但这只是迁移路径判断，本轮未验证本地模型的任务成功率；聊天与Embedding后端还须分别核对，不能只改一个地址就声称全流程本地化。

首轮建议固定因子任务和预测模型，先测生成/修复能力；自动搜索新因子、模型联合优化放后续。原默认test区间参与反馈的问题需要单独封存最终测试集解决。

## 4. 与Intern PoC的具体衔接

建议先做“**自然语言因子实现与自动校验**”，备选为“**本地文档证据问答**”。这是候选排序，尚未选定或部署最终模型。

| 项目 | 拟记录内容 |
|---|---|
| 环境 | GPU/VRAM、CPU/RAM、OS/驱动、模型与tokenizer精确版本、量化、推理引擎 |
| 任务 | 小规模固定任务集，题目来源、允许字段/工具、输入截止时间、参考实现或证据答案 |
| 对照 | 同一LLM基础Prompt与结构化约束/反馈；RAG与不检索；传统规则/参考代码只作为基线 |
| 质量 | 代码正确性或事实/引用正确性；失败分类、模型编造、时间泄漏、模型修复效果 |
| 性能 | 冷启动与预热分开；TTFT、完整生成延迟、输入/输出token、吞吐、峰值显存；工具运行另外计时 |
| 本地性 | 模型/Embedding实际调用地址与网络依赖；数据、日志和模型产物的位置 |
| 范围 | 本轮先推理与任务能力，不预设必须重训/微调；不将生成代码直接接交易执行 |

工作站GPU/显存尚未得到信息，因此不承诺具体模型尺寸、上下文容量或延迟。公开模型下载、资料处理、推理服务和评价都需要版本固定；本轮研究只能提供可检验的路线，性能结论由后续本地实验产生。

源码和论文索引见[外部本地LLM参考](../reference/local-llm/README.md)，本轮完整性检查见[审计](../audits/2026-09-09-local-llm-research/README.md)。
